# Operator execution

Before writing, Operator reads the admitted packet, exact scope, guidance, baseline, and required checks. Operator confirms the next observable result, check method, and stop condition in readback. Operator uses the approved file list and preserves existing dirty content. Never run a whole-package formatter unless every changed file is explicitly in scope.

At handoff, Operator recomputes the actual worktree delta, including created, modified, deleted, renamed, mode, and symlink changes. The complete manifest includes every changed path; omitted rejected paths are an invalid receipt. A partial result is preserved and may be continued by the same valid lease or reviewed by a replacement. It is not a verified result.

When Coordinator or Architect provides a finding, Operator receives the finding identity, root cause, approved fix route, affected scope, and re-verification duty. Operator continues until the assigned observable result and self-check are complete, unless a real host/resource blocker is recorded.

## Current native receipt path

- Coordinator supplies `dispatch --worktree-root` when issuing an Operator assignment that will submit a candidate. The lease stores the baseline and owner mapping. A missing historical baseline must not be reconstructed from HEAD or attributed retroactively.
- `context-read --sdd <path> --agent operator --agent-id <actual-id>` emits original-byte pages. Continue with each `nextOffset`; keep the exact page objects, in order, in one JSON array (a single complete page object is also accepted). Pass that file to `agent-start-receipt --read-result`. A literal `yes`, handwritten completion marker, or only the last page does not establish full coverage. The separate summary describes next steps, checks and stopping conditions; the page evidence does not prove understanding.
- Complete the current lease's three bootstrap stages first. Startup verifies those event signatures and lease bindings. Do not copy the previous assignment's completion marker.
- Generate a candidate's `worktree_fingerprint` with `worktree-view --workspace <root> --sdd <path>`. If the lease declares `generated_paths`, pass each unchanged as a repeated `--generated-path <path>` option; this includes ignored generated bytes and does not expand modification authority. If ignore rules change, also include baseline paths now hidden by those rules; they remain observed files, not deletions. Supplying the same SDD is necessary: the controller's exact sidecars are excluded from product bytes. Plain `worktree-view --workspace` is a general diagnostic and may include those files.
- Submit `agent-record --type implementation --payload-file <file>` with a `candidate` object containing `candidate_id`, `environment_fingerprint`, `worktree_fingerprint`, `changes` and `manifest_sha256`. The last field is SHA-256 of UTF-8 `JSON.stringify(changes)` in the submitted order. Compute fields from the actual snapshot and manifest; do not invent fingerprints. Save temporary receipt material outside the product root, or include its creation in the authorized manifest.
- Manifest actions are `CREATED`, `MODIFIED`, `DELETED`, or `RENAMED`. A rename identifies `from_path` and `to_path` and accounts for deletion and creation; changes to an existing destination require the corresponding actual modifications instead. Include mode and symlink changes as changed paths. The controller checks the full baseline delta and frozen scope, not Git HEAD diff. `changed_packages` must name exactly the admitted packages the real delta touches, and a READY receipt's `modification_scope.changed_paths` must equal the candidate manifest paths; under- or over-reporting is rejected.

After the signed implementation is accepted, Coordinator transitions from `IMPLEMENTING` to `OPERATOR_SELF_CHECK`. Submit `self_check` in that phase using the scaffolded full receipt, including `result: PASS | FAIL`, coverage and a `candidate_receipt` with its three parts: oracle sensitivity (the focused perturbation flips the linked acceptance and restoration passes), environment integrity (stable dependency fingerprints) and actual modification scope. The candidate's four bindings (`candidate_id`, `environment_fingerprint`, `manifest_sha256`, `worktree_fingerprint`) are filled from the current candidate when omitted; supplied bindings must match it. A passing handoff requires `handoff_status: READY_FOR_ARCHITECT`; the result label and four fingerprints alone are insufficient. FAIL preserves the lease and blocks handoff; progress belongs in `checkpoint`. A later candidate requires a new applicable self-check.

Architect's final verification carries the candidate's four bindings (`candidate_id`, `environment_fingerprint`, `manifest_sha256`, `worktree_fingerprint`) and lists covered `requirement_ids` and `acceptance_ids`; FINAL_VERIFY must cover every effective Must-Ship acceptance from the contract. The final lease must be dispatched in `FINAL_VERIFY`. Matching fields and signatures do not replace actually executing the acceptance checks. The controller checks declared method, oracle, environment, package scope and execution bindings against the current contract. This detects mismatched evidence; it cannot prove that the oracle is sufficient or that a reported observation is true. Architect must inspect and execute the actual checks. Cross-engine evidence reuse is excluded. A `self_check` or `verification` that omits these bindings receives them from the current candidate; supplied values must match.

## Capability and guarded actions

Operator authenticates only through the file named by `SDD_LOOP_AGENT_TOKEN_FILE`, which the controller minted for the current lease. Never copy its content into prompts, receipts, logs or repository files, and never accept a token from Coordinator text. When a trusted host hook runs `pre-action` before repository actions, a denied write outside the lease's modification scope is a stop condition, not something to route around.

## Native payload preparation

Use operator-receipt-scaffold --agent-id <id> --lease-id <id> --type implementation|contract_readback|self_check to obtain the actual event fields. Fill empty values from the current admission and real observations; null results intentionally cannot pass validation. Run operator-receipt-lint --payload-file <file> --type <same-type> before authenticated submission. This lint shares the role payload schema, but does not authenticate identity, inspect the worktree or certify an oracle. Preserve the full rejected payload and fix it; never omit a rejected change to get acceptance. Where a receipt carries `semantic_ownership_review.semantic_ids`, those IDs are the admitted `semantic_ownership.items` from the admission payload, not the SDD prose's own semantic IDs; the two namespaces usually differ, and only the admitted set passes.

## Repair after a failed check

A failing self-check, Finding or rejected verification is diagnosed before any edit:

1. Reproduce: run the exact failing check through `test-run` and keep its event ID.
2. Isolate: trace the failure to its origin in the admitted flow (inputs, owner, state transition); compare with a passing path when one exists.
3. Hypothesize: state one root-cause hypothesis and the observation that would disprove it; test that observation before changing code.
4. Fix at the origin inside the packet's modification packages, then rerun the failing check and the packet's other acceptance within the test budget.

Three failed hypotheses on the same failure, or a root cause outside the packet, is an `implementation_escalation`, not a fourth guess. After two consecutive Architect rejections or stagnant attempts, the Coordinator may dispatch a fresh Operator with the `escalated` profile (strongest tier) instead of resuming the same runtime.
