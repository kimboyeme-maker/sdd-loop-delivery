# Role boundaries

Supervisor reports public progress and routes user decisions. Coordinator owns admission, scope, lease routing, guidance, recovery decisions, and the final route. Operator implements the admitted packet, runs self-checks, and reports a complete candidate. Architect independently verifies the candidate, records concrete Findings, and may propose a simpler or clearer approach; Architect does not override Coordinator or create a parallel decision loop.

An agent response ending is a communication boundary, not task completion. Same unfinished work, healthy runtime, and valid lease use continuation. New runtime requires diagnosis, old runtime stop/revocation evidence, and a new lease. Use the exact host-returned identity handle, including a canonical task path when the host uses that as its handle. Do not substitute a requested name for a returned handle. Identity alone does not prove model, isolation, capability ownership or resource release; those require their own evidence.

`coordinator-preflight` validates submitted receipt fields only. Its successful exit and `schemaValid` do not attest host provenance, model execution, or isolation; use actual host evidence for those claims. Do not turn a local schema result into authority or invent a host attestation field.

## Reusing reading

When the same role runtime confirms it still retains the necessary understanding, use `context-read --agent operator` (or `architect`) with `--agent-id` and `--retained-understanding`. The controller authenticates the active lease and omits only unchanged sources covered by that runtime's signed reading evidence in the current epoch. Save every page, including a zero-byte complete page, for `agent-start-receipt`. Without retained understanding, omit the flag and read normally. `--fresh` disables ordinary historical reuse. Reuse does not skip the new assignment's route/readback obligations.

For an Operator refreshing context within its current lease, submit `context_refresh` with `read_result` containing the complete page JSON file path and `summary` describing the updated understanding. The controller derives `reading` from validated pages; a caller-supplied reading ledger cannot replace them. Normative changes still require amendment; refresh does not extend scope or the lease deadline.

During Architect preparation, read with `--agent architect --agent-id <actual-id> --prepared-id <grant-id>`; include `--fresh` when the grant is fresh. This reads the frozen preparation snapshot. Submit complete pages through `prepare-record context_ready`. Formal dispatch uses `--prepared-id` to validate that signed receipt; subsequent ordinary role reading with retained understanding can reuse unchanged sources. Missing or incomplete preparation falls back to ordinary startup without waiting. Formal verification still requires its own lease, bootstrap, current candidate and independent verdict.

Unchanged unique sections can be reused within a changed source only when its section layout remains identical. Repeated headings or added, removed, or reordered sections force a whole-source read. Preserve the full page sequence; a reused-fragment reference never replaces a route/readback check or an updated prerequisite.

Before creating another runtime, inspect `runtime-view.candidates`. It lists known role identities even when no lease is active, together with history exclusions, the latest authenticated host observation and current grants. `eligible` means the recorded facts permit considering reuse; it does not attest present liveness, issue a lease or bypass independent verification. Reconfirm stale control with the owner/ancestor, then use normal dispatch. An existing active grant uses the continuation rules rather than overlapping assignments.

## Identity and credentials

- Each role writes only its own events: Coordinator through `record`, `transition` and dedicated commands; Operator/Architect through `agent-record` under their active lease. The controller mints each role credential into a private mode-0600 file and returns only its locator; the role runtime reads it through `SDD_LOOP_AGENT_TOKEN_FILE`. Coordinator keeps `SDD_LOOP_COORDINATOR_TOKEN` private, never handles role tokens, and never synthesizes, paraphrases or replays role evidence. Same-OS-account file access remains instruction-enforced, not kernel-isolated.
- Coordinator authority changes (`auth-bootstrap` with identity, `coordinator-takeover`, `bootstrap-recover`) bind the actual host spawn receipt of that Coordinator before rotating authority.
- A terminal controller keeps its outcome, history, product counters and evidence immutable. Entering SHIP or BLOCKED revokes any outstanding lease and preparation in the same commit; afterwards only resource wind-down records (`runtime-record` `observe`, `retire`, `close_result`) are accepted, so host runtimes can still be stopped, retired and closed. A paused controller accepts user-control resume/cancel, authority recovery and the same wind-down records.
- Controller state binds the committed event log (line count, byte length and a per-line hash chain). Removed, reordered, inserted or altered history fails closed (`EVENT_LOG_HISTORY_MISMATCH`); only an interrupted commit's extra tail is recoverable. Closing a round records a checkpoint at the earliest event the current admission, candidate or a live grant still needs. Commits append and verify only the lines after it, and so do round-scoped reads (`test-run` and its registration); every read of history as a whole (`status`, `audit`, `SHIP` and each rule about history) verifies the entire log, so a change before the checkpoint is found there. `audit` additionally authenticates every event of the current Coordinator authority, and `SHIP` requires `AUTHENTIC_CURRENT_EPOCH`.
- The Coordinator credential lives in a controller-minted mode-0600 file: `auth-bootstrap`, `coordinator-takeover` and `bootstrap-recover` mint it when no token is supplied, return `capabilityFile`, and keep the locator in raw state. After context compaction, set `SDD_LOOP_COORDINATOR_TOKEN_FILE` to that locator instead of rotating authority.
- Role membership is conversation-local and permanently role-stable: one runtime handle is never both Operator and Architect, and any historical Coordinator is excluded from product roles.
- Missing, malformed, expired, mismatched or proxy-written role evidence is untrusted and cannot unlock a transition or support SHIP. Suspected token disclosure is an authority incident: revoke, distrust post-exposure evidence, recover and redispatch.
- An agent that exits after changing code but before recording evidence leaves untrusted partial work: continue the same healthy lease or replace under the preservation protocol. Never impersonate the missing role.
- Role events are Ed25519-signed per lease; Coordinator decisions carry epoch-key proofs verifiable after rotation. The local controller provides provenance and gating, not kernel-backed model identity between processes of one OS account.
- Credentials use `SDD_LOOP_COORDINATOR_TOKEN_FILE` and `SDD_LOOP_AGENT_TOKEN_FILE`.
